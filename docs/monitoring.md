# 監視データ取得

実装の入口はsrc/hardware.rsのSamplerとSnapshotです。監視値の取得はUIから分離し、失敗はOptionのNoneとエラー情報で表現します。

## CPU

CPU名はWindowsレジストリのProcessorNameStringから取得します。使用率はPDHの英語カウンターを使い、OSの表示言語に依存しないようにします。

- 全体: Processor Information(_Total)の% Processor Time。
- 論理CPU別: Processor Information(group,index)の% Processor Time。アクティブな全プロセッサグループを列挙します。
- レートカウンターには前回値と測定間隔が必要です。起動直後や採取失敗後の準備中は0%扱いにせず、N/Aとします。
- カウンターのステータスと値を検証します。取得不可・非有限値を有効な使用率と混同しないでください。

物理コアの対応はGetLogicalProcessorInformationEx(RelationProcessorCore)から取得します。同じ物理コアの論理CPU使用率を平均し、SMTの一方だけを選ぶ方法は使いません。兄弟の値が1つでも取得できなければ、その物理コアはN/Aです。

論理CPUの識別子は(group,index)です。物理コアの画面番号は列挙したコアの連番で、論理CPU番号とは意味が異なります。物理トポロジー取得に失敗すると物理コアのリストは空になり、論理CPUであるかのような代用は行いません。

## RAM

GlobalMemoryStatusExで物理メモリの総量・利用可能量を取得し、使用量は総量から利用可能量を引きます。減算はsaturating_subとし、総量0やAPI失敗はN/Aです。

画面のGはGiB（1,073,741,824バイト）です。使用率バーは使用量／総量で計算します。RAM・VRAMとも十進GBに置き換えた場合は表示仕様と資料を同時に更新してください。

## NVIDIA GPU

src/nvml.rsでNVIDIAドライバーのnvml.dllをSystem32検索に限定して動的ロードし、必要なexportを確認します。NVML初期化後にGPUを列挙し、機種名・使用率・温度・VRAMを取得します。

使用率・温度・VRAMはそれぞれ成功判定を行い、一部だけ取得できる場合も有効な項目を表示します。VRAMは総量0・無効な最大値・使用量が総量を超える値などを除外します。未対応GPU、DLL不在、NVMLエラーはN/Aとエラー情報で扱います。現時点でAMD／Intel GPUの監視は実装していません。

DLL、関数ポインター、NVMLデバイスは監視スレッドで所有します。C ABIの型・構造体レイアウトを変える場合は公式定義を確認してください。初期化成功にはShutdownを対応させ、その後にFreeLibraryします。

## 更新・失敗・制約

更新間隔は設定の値（既定1秒）です。UI側はsampled_atから経過時間を見て、監視間隔の3倍（最低3秒）を超えた値をN/Aにします。STALE／取得エラーはトレイのツールチップへ表示し、probeでも診断できます。

PDH・NVML・CPUトポロジーは起動時に初期化します。現状、初期化失敗からの自動再初期化や、起動後のGPU追加・CPU構成変更の再列挙は行いません。再試行やホットプラグ対応を追加する場合は、終了時の所有権と正常値／失敗の区別を維持してください。

CPU温度はユーザーの指示で延期しています。再開時はRust単体での取得を優先し、通常API・必要なドライバー・再配布条件を調べてから方式を決めます。GPU温度の既存NVML取得とは別の課題です。

実機条件と確認範囲は[phases.md](phases.md)、性能への影響は[performance.md](performance.md)を参照してください。

GPU列挙時の権限エラーや無効なハンドルはデバイスごとに保持し、正常なGPUの監視を継続します。失敗したGPUには個別のN/Aとエラーを表示します。
