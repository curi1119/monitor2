# 旧版とmonitor2の性能比較

2026-10-01に同じ実機上で同時測定しました。
最終試作版の起動時動作と参照寿命を修正した後、再測定した結果です。

## 条件

- CPU: AMD Ryzen 7 5800X3D、16論理CPU。
- GPU: NVIDIA GeForce RTX 4070 Ti、ドライバー616.56。
- 旧版: 起動済みのMonitor、PID 20724、C:\Monitor.exe。
- 試作: Rust 1.98.1のreleaseビルド、通常の常駐モード、PID 10900。
- 両アプリとも約1秒更新。試作版は起動後10秒待ってから測定。
- 2026-10-01 07:22:11 JST開始、120.975秒、2秒間隔で61サンプル。
- 画面操作ツールが試作に干渉しない状態で測定。旧版は終了・再起動していない。
- 実行ファイル: 249,856 bytes（244 KiB）。
- 試作実行ファイルSHA-256: E120D6E3A99DF2AE755D22FE83754CE3E2F98899BA3E755E18B9F41F26C48419

## 結果

| 指標 | 旧版 Monitor | monitor2試作 | 試作の変化 |
|---|---:|---:|---:|
| 測定区間のCPU時間 | 0.625秒 | 0.250秒 | 約60%減 |
| 平均CPU使用率（1論理CPU=100%） | 0.5166% | 0.2067% | 約60%減 |
| 平均CPU使用率（16論理CPU全体=100%） | 0.0323% | 0.0129% | 約60%減 |
| 平均Working Set | 49.745 MiB | 42.716 MiB | 約14%減 |
| 平均Private Bytes | 46.753 MiB | 27.436 MiB | 約41%減 |
| Private Bytes開始→終了 | 46.750→46.750 MiB | 27.508→27.359 MiB | 区間中に増加せず |
| ハンドル数開始→終了 | 568→568 | 250→248 | 増加せず |

CPU使用率は、プロセスのTotalProcessorTimeの差を実測時間で割って計算しています。
CPU時間はカーネル時間とユーザー時間の合計です。
Working Setは常駐しているメモリ、Private Bytesは共有されないコミット済みメモリの指標です。
メモリは各サンプルの算術平均で、単位はMiBです。

この条件では試作版のCPU時間とメモリ使用量が少ない結果でした。
CPU消費の絶対量は両版とも小さく、短時間・単一実機の比較です。
旧版は長時間起動済み、試作は新規起動という条件差もあります。
更新タイミング、バックグラウンド負荷、GC、APIの違いにより結果は変動します。
NVAPIを使う旧版とNVMLを使う試作では、GPU取得値の意味や処理内容も完全には同一ではありません。
この測定で長時間動作の安定性やリークがないことまでは判断できません。

## Rust 1.98.1と1.100.0の比較（2026-11-14）

monitor2 0.2.1の同じソース（1a28dba1081beeb07574d3a7f60e09b28034a33c）とCargo.lockを使い、Rust 1.98.1と1.100.0でそれぞれreleaseビルドしました。未コミット差分は文書だけです。別々のtarget-dirを使い、LTO有効・codegen-units=1・strip有効の既存設定を維持しました。これは冒頭の旧版Monitorとの比較とは異なり、Rustツールチェーンだけを変えた比較です。

### 条件

- Windows 11 Pro build 26300、Ryzen 7 5800X3D（16論理CPU）、RTX 4070 Ti、ドライバー32.0.16.1656。
- 通常権限で2プロセスを同時起動。各回新規起動から10秒待ち、約121秒を2秒間隔で3回測定（各59サンプル、合計177サンプル／版）。実際のサンプリング時刻はCSVに記録。
- デフォルトテーマ、1秒更新、論理コア、使用率%表示、CPU番号非表示、最前面オン、自動起動オフ、ドラッグ・左クリックスルーともオン。
- 専用LOCALAPPDATAを版ごとに用意し、ユーザー設定は変更していません。表示位置は(100,100)と(300,100)。2回目は起動順と左右の指定位置を入れ替えました。
- 2026-11-14 10:26:26、10:28:37、10:30:49 JSTに測定開始。測定中にエージェントによるビルド・UI操作は行っていません。OSや他アプリのバックグラウンド負荷は制御していません。
- 測定には既存の[measure-processes.ps1](../scripts/measure-processes.ps1)を使用。原データのlegacyがRust 1.98.1、prototypeがRust 1.100.0です。測定終了後、比較用プロセスだけを停止しました。既定のRustは1.100.0のままです。

### 結果

| 指標 | Rust 1.98.1 | Rust 1.100.0 |
|---|---:|---:|
| 1回目のCPU時間 | 0.234375秒 | 0.187500秒 |
| 2回目のCPU時間 | 0.296875秒 | 0.343750秒 |
| 3回目のCPU時間 | 0.203125秒 | 0.109375秒 |
| CPU時間合計（363.090秒） | 0.734375秒 | 0.640625秒 |
| 平均CPU使用率（1論理CPU=100%） | 0.2023% | 0.1764% |
| 平均CPU使用率（16論理CPU全体=100%） | 0.01264% | 0.01103% |
| 平均Working Set | 39.870 MiB | 39.882 MiB |
| 平均Private Bytes | 27.066 MiB | 26.872 MiB |
| ハンドル数開始→終了（1回目） | 191→192 | 191→192 |
| ハンドル数開始→終了（2・3回目） | 185→186 | 185→186 |
| EXEサイズ | 676,864 bytes（661 KiB） | 680,960 bytes（665 KiB） |

CPU使用率は3回のCPU時間合計を実測時間合計で割り、メモリは全177サンプルの算術平均です。CPU時間合計は新版が約12.8%少ない観測値でしたが、2回目には優劣が逆転しています。差の絶対量は合計0.09375秒と小さく、短時間の3回測定から明確な高速化とは断定しません。

Working Setは約0.011 MiB増、Private Bytesは約0.194 MiB減で、メモリ使用量はほぼ同等です。各回のPrivate Bytesは両版とも終了時に開始時よりわずかに少なく、ハンドル数の増分も両版で同じでした。EXEは4 KiB（約0.6%）増えました。この条件で大きな性能悪化は観測されませんでしたが、長時間のリーク、他テーマ・更新間隔、他のPCの性能は未検証です。ビルド所要時間は公平な反復測定をしていないため比較対象に含めません。
